今のセッションで自分 (Claude) が触ったファイルだけをコミットする。追加指示: `$ARGUMENTS`

**大原則**: `git add .` / `git add -A` / `git add -u` / `git commit -a` は使わない。必ず `git add -- <path>` の**明示パス指定**でステージする。他セッションの差分を巻き込まないため。

## 手順

### 1. 自分がこのセッションで触ったファイルを列挙する

- 今のセッション中に Edit / Write / NotebookEdit / MultiEdit / Bash 経由で **作成・変更・削除・リネーム**したリポジトリ内のファイルを全て列挙する
- 過去のセッションの記憶は使わない。**今のセッションのコンテキストに残っているもののみ**
- スクラッチパッド配下のファイルはそもそもリポジトリ外なので対象外
- **compaction が入っており自分の編集履歴を完全に再現できないと判断した場合は、コミットを実行せず、その旨をユーザーに正直に報告して指示を仰ぐ**（誤って別セッションの差分を含めるくらいなら止まる）

### 2. 現状を把握する

- `git status` を実行し、リポジトリの staged / unstaged / untracked 状態を確認する
- 自分が触った覚えがないのに変更が入っているファイルは「別セッション由来と思われる」として**対象外**にする（次段のステージング対象に含めない）
- 逆に、自分が触ったつもりでも `git status` に差分が出ていないファイル（あとで元に戻した等）はコミット対象から除外する
- 同一ファイルに自分の編集と別セッションの編集が混在している疑いがある場合は、コミットを保留してユーザーに報告する（hunk 単位で分けるか、手動対応するかの判断を仰ぐ）

### 3. 対象ファイルをステージする

- 対象ファイルを `git add -- <path1> <path2> ...` で**明示パス指定**でステージする
- 削除ファイルも同様に `git add -- <path>` で反映される（`git rm -- <path>` を使ってもよい）
- `git add .` / `-A` / `-u` は**使わない**
- 対象ファイルに git 管理外（untracked / `.gitignore` 対象）のものが含まれる場合は、`~/.claude/CLAUDE.md` の方針に従い、対象パスと意図を示してユーザーに確認を取る

### 4. ステージ内容を確認する

- `git status` を実行し、意図したファイルのみ staged になっていることを確認する
- `git diff --cached` を実行し、差分の中身に想定外の変更や秘密情報（`.env` / credentials 等）の混入がないか確認する
- 想定外があればコミットを止めてユーザーに報告する

### 5. コミットする

- 直近の `git log` を参照し、そのリポジトリのメッセージスタイル（プレフィックス、言語、粒度）に合わせてコミットメッセージを作成する
- 引数 `$ARGUMENTS` があれば、その指示をメッセージに反映する
- `~/.claude/CLAUDE.md` の方針に従い、末尾に `Co-Authored-By: Claude <モデル名> <noreply@anthropic.com>` を必ず付ける。モデル名は今この skill を実行している自分の実モデル名（例: `Claude Opus 4.7`）
- コミットメッセージは HEREDOC（`git commit -m "$(cat <<'EOF' ... EOF)"`）で渡す

### 6. 結果を報告する

- 生成されたコミットのハッシュとメッセージ
- **コミット対象にしたファイル一覧**
- **コミット対象外にしたファイル一覧**（別セッション由来と判断したもの、および理由）
- コミット後の `git status` で残っている未コミット差分があればその内容

## 注意

- **禁じ手**: `git add .` / `git add -A` / `git add -u` / `git commit -a` — いずれも他セッションの差分を巻き込むため使用禁止
- **迷ったら止まる**: 「自分が触ったかどうか判断がつかないファイル」があれば、勝手に含めず・勝手に除外せず、ユーザーに確認する。誤って他セッションの差分を含めるのが最悪
